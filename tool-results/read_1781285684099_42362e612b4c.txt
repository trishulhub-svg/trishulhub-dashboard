The difference between the two is explained as follows. For detailed introduction, please refer to <a href=\"/document/ukTMukTMukTM/uETNz4SM1MjLxUzM/v3/guides/scope_authority\" class=\"internal-link\" target=\"_self\">Introduction to contacts permission scope</a> and <a href=\"/document/home/introduction-to-scope-and-authorization/availability\" class=\"internal-link\" target=\"_self\">Configure application availability scope</a>.</p><ul class=\"md_render-table_solid md_render-table\"><li>The contacts permission scope defines the data scope of departments and users that the application can obtain when calling the contacts API. The application cannot access data that is not within the contacts permission scope. For example, when calling the <a href=\"/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/patch\" class=\"internal-link\" target=\"_self\">Modify user partial information</a> interface as an application to modify user information, the user must be within the contacts permission scope of the application.</li><li>The available scope of an application defines the scope of enterprise members who can use the application. Enterprise members not in the scope do not have permission to use the application. For example, if the available scope of an application includes user A but not user B, user A can search and use the application in the Lark client, but user B cannot.</li></ul><h3 id=\"9a31839f\" tabindex=\"-1\">What permissions are required to call the contacts interface?</h3><p>The contacts currently includes several modules such as members, departments, and user groups. Each module will provide a corresponding API interface to facilitate intelligent system docking. When you use an interface, the relevant permission requirements fall into three main categories.</p><div class=\"md-table_table-wrapper\"><table class=\"md-td_render-block_table\"><thead class=\"md-td_render-block_thead\"><tr class=\"md-td_render-block_tr\"><th class=\"md-td_render-block_th\" style=\"width: 25%;\">Permission type</th><th class=\"md-td_render-block_th\" style=\"width: 75%;\">Description</th></tr></thead><tbody class=\"md-td_render-block_tbody\"><tr class=\"md-td_render-block_tr\"><td class=\"md-td_render-block\"><p>Interface permission requirements</p></td><td class=\"md-td_render-block\"><p>Defines whether the application has permission to call this interface. Without permission, the interface cannot be accessed.</p></td></tr><tr class=\"md-td_render-block_tr\"><td class=\"md-td_render-block\"><p>Contacts permission scope</p></td><td class=\"md-td_render-block\"><p>Define the data range of departments and users that the application can query or operate. When you call the interface to obtain or operate certain data, if you do not have the contacts permission for the data, an error message will be reported indicating that you have no permission. For more information, see <a href=\"/document/ukTMukTMukTM/uETNz4SM1MjLxUzM/v3/guides/scope_authority\" class=\"internal-link\" target=\"_self\">Detailed explanation of scope of authority</a>.</p></td></tr><tr class=\"md-td_render-block_tr\"><td class=\"md-td_render-block\"><p>Field permission requirements</p></td><td class=\"md-td_render-block\"><p>Since some entities (such as users) have different sensitivities to different fields (for example, a user's mobile phone number is relatively sensitive), you need to apply for additional permissions to obtain such fields.
